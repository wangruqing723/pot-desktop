# 手动翻译只做纯手动，不做自动兜底

「手动翻译」的初衷是把某个服务留作兜底：其它服务不可用时才用它。一个更自动的做法是让手动实例在"其它已启用实例全部失败后"自行发起翻译，但我们选择**纯手动**——永远等用户点击。

理由：翻译窗口里每张卡片的加载/成功/失败都是各自的组件本地状态，彼此不可见，自动兜底需要引入一套跨卡片的状态登记表，还要定义「不可用」到底是 reject、空结果、语言不支持还是超时未返回；更关键的是，它会在用户没点击的情况下自动消耗付费额度，而"不想让它自动跑"往往正是把一个服务设为手动的原因。纯手动在兜底场景下的代价只是一次点击。

将来若要加自动兜底，可在不改 `manualTranslate` 语义的前提下叠加（例如另设一个"失败后自动兜底"选项），本决策不构成阻碍。
